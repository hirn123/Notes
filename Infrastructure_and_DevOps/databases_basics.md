# Базы данных: основы, резервное копирование и SQL

## 1. Что такое база данных и СУБД

**База данных (БД)** — это организованная коллекция структурированных данных, хранящихся в электронном виде. Данные организованы в **таблицы**, которые состоят из **строк** (записей) и **столбцов** (полей). Каждая таблица описывает один тип сущности (пользователи, заказы, товары).

**СУБД (Система управления базами данных)** — это программное обеспечение, которое позволяет создавать, читать, обновлять и удалять данные в базе (CRUD-операции). СУБД управляет доступом, обеспечивает целостность данных и обрабатывает конкурентные запросы.

**Популярные СУБД:**

| СУБД | Тип | Особенности |
|---|---|---|
| **MySQL / MariaDB** | Реляционная (SQL) | Самая распространённая в веб-разработке. Входит в стек LAMP/LEMP |
| **PostgreSQL** | Реляционная (SQL) | Расширенная, соответствует стандартам SQL, поддерживает JSON, GIS |
| **SQLite** | Реляционная (SQL) | Встраиваемая, не требует отдельного сервера (файл на диске) |
| **MongoDB** | Документоориентированная (NoSQL) | Хранит данные в формате JSON-подобных документов |

**Реляционные vs NoSQL:**
- **Реляционные** (MySQL, PostgreSQL) — данные строго структурированы, схема таблиц задаётся заранее, связи между таблицами через внешние ключи. Идеальны для транзакционных систем (банки, интернет-магазины).
- **NoSQL** (MongoDB, Redis) — гибкая схема, данные могут быть неструктурированными. Используются для больших объёмов данных, кэширования, real-time приложений.

## 2. Язык SQL

**SQL (Structured Query Language)** — стандартный язык для работы с реляционными базами данных. Все основные СУБД (MySQL, PostgreSQL, SQLite) поддерживают SQL, хотя диалекты могут немного отличаться.

**Основные группы команд SQL:**

| Группа | Назначение | Примеры команд |
|---|---|---|
| **DDL** (Data Definition Language) | Определение структуры | `CREATE`, `ALTER`, `DROP` |
| **DML** (Data Manipulation Language) | Работа с данными | `SELECT`, `INSERT`, `UPDATE`, `DELETE` |
| **DCL** (Data Control Language) | Управление правами | `GRANT`, `REVOKE` |

## 3. Резервное копирование: создание дампа БД (mysqldump)

**Дамп** — это снимок базы данных (структура таблиц + данные) в виде SQL-файла. Используется для резервного копирования, миграции на другой сервер или восстановления после сбоя.

**Базовый синтаксис `mysqldump` (для MySQL/MariaDB):**
```bash
mysqldump -u <пользователь> -p <имя_базы> > /путь/к/файлу/dump.sql
```

**Пример — дамп одной базы:**
```bash
mysqldump -u root -p myapp_db > /backup/myapp_2026-01-21.sql
```

**Пример — дамп всех баз:**
```bash
mysqldump -u root -p --all-databases > /backup/all_db.sql
```

**Пример — дамп с сжатием (экономит место):**
```bash
mysqldump -u root -p myapp_db | gzip > /backup/myapp.sql.gz
```

**Важные флаги:**
- `--single-transaction` — для InnoDB-таблиц создаёт согласованный снимок без блокировки таблиц (позволяет делать дамп на работающем сервере).
- `--routines` — включает хранимые процедуры и функции.
- `--triggers` — включает триггеры.

**Безопасность:** передача пароля через `-p` в командной строке оставляет его в истории shell. Более безопасный способ — создать файл `~/.my.cnf` с правами `600`:
```ini
[client]
user=root
password=ваш_пароль
```
Тогда команда будет выглядеть так: `mysqldump myapp_db > backup.sql`.

## 4. Импорт дампа БД из консоли

Импорт — восстановление базы данных из SQL-файла. Выполняется через клиент `mysql`.

**Базовый синтаксис:**
```bash
mysql -u <пользователь> -p <имя_базы> < /путь/к/файлу/dump.sql
```

**Пример:**
```bash
mysql -u root -p myapp_db < /backup/myapp_2026-01-21.sql
```

**Если дамп сжат (`.gz`):**
```bash
gunzip < /backup/myapp.sql.gz | mysql -u root -p myapp_db
```

**Важно:** база данных, в которую выполняется импорт, должна существовать. Если дамп содержит команду `CREATE DATABASE`, можно сначала создать базу, затем импортировать.

## 5. Выборка данных по условию (SQL SELECT)

**SELECT** — команда для чтения данных из таблицы. **WHERE** — фильтр, который возвращает только строки, удовлетворяющие условию.

**Базовый синтаксис:**
```sql
SELECT <столбцы> FROM <таблица> WHERE <условие>;
```

**Пример — все столбцы из таблицы `users`:**
```sql
SELECT * FROM users;
```
`*` — сокращение для «все столбцы». В production-коде `SELECT *` считается плохой практикой, так как при добавлении нового столбца результаты запроса изменятся.

**Пример — выборка конкретных столбцов:**
```sql
SELECT id, name, email FROM users;
```

**Пример — фильтрация по условию:**
```sql
SELECT * FROM users WHERE status = 'active';
```

**Пример — несколько условий (AND, OR):**
```sql
SELECT * FROM users WHERE status = 'active' AND age >= 18;
```

**Пример — сортировка результатов (ORDER BY):**
```sql
SELECT * FROM users WHERE status = 'active' ORDER BY created_at DESC;
```

**Пример — ограничение количества строк (LIMIT):**
```sql
SELECT * FROM users LIMIT 10;
```

**Пример — агрегация (COUNT, SUM, AVG):**
```sql
SELECT COUNT(*) FROM users WHERE status = 'active';
SELECT AVG(price) FROM products WHERE category_id = 2;
```

**Логика работы WHERE:** условие — это логическое выражение, которое проверяется для каждой строки. Если выражение истинно — строка включается в результат, если ложно — отбрасывается.

## 6. Назначение прав пользователю (SQL GRANT)

**GRANT** — команда DCL для выдачи привилегий пользователю или роли. В MySQL/MariaDB сначала нужно создать пользователя, затем выдать права.

**Создание пользователя:**
```sql
CREATE USER 'app_user'@'localhost' IDENTIFIED BY 'strong_password';
```

**Выдача прав на конкретную базу (все привилегии):**
```sql
GRANT ALL PRIVILEGES ON myapp_db.* TO 'app_user'@'localhost';
```

**Выдача прав на конкретную таблицу (только чтение):**
```sql
GRANT SELECT ON myapp_db.orders TO 'app_user'@'localhost';
```

**Выдача конкретных привилегий (SELECT, INSERT, UPDATE, DELETE):**
```sql
GRANT SELECT, INSERT, UPDATE, DELETE ON myapp_db.* TO 'app_user'@'localhost';
```

**Применение изменений (для MySQL):**
```sql
FLUSH PRIVILEGES;
```

**Проверка выданных прав:**
```sql
SHOW GRANTS FOR 'app_user'@'localhost';
```

**Отзыв прав (REVOKE):**
```sql
REVOKE DELETE ON myapp_db.* FROM 'app_user'@'localhost';
```

**Уровни привилегий в MySQL:**
- `*.*` — все базы данных на сервере (глобальный уровень).
- `myapp_db.*` — все таблицы в конкретной базе.
- `myapp_db.orders` — конкретная таблица.
- `myapp_db.orders(id, status)` — конкретные столбцы (в MySQL 8.0+).

**В PostgreSQL** синтаксис похож: `GRANT SELECT ON ALL TABLES IN SCHEMA public TO app_user;`.
