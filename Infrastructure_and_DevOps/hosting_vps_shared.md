## 1. Что такое хостинг?

**Определение:** Аренда вычислительных мощностей (место на диске, процессорное время, оперативная память) и доступа в интернет для размещения сайта или приложения.

> **Аналогия:** Можно построить свой дом (купить сервер и поставить дома), но это дорого — нужны электричество, охлаждение и интернет. Или снять квартиру (арендовать хостинг), где всё это уже есть.

**Что даёт хостинг-провайдер:**
- **Uptime** — сервер работает 24/7.
- **Канал связи** — широкий интернет-канал, чтобы сайт быстро открывался.
- **Электричество и охлаждение** — сервер стоит в дата-центре (ЦОД).
- **IP-адрес** — чтобы браузер мог найти сайт.

## 2. Процесс развертывания сайта

Сам по себе хостинг — это просто «место». Чтобы сайт открывался по домену, на этом месте нужно запустить несколько программ. Классический набор для динамического сайта (например, на WordPress или самописного на PHP) называется **LEMP** или **LAMP** (Linux, Nginx/Apache, MySQL, PHP).

1.  **Загрузка файлов:** Копирование файлов сайта (HTML, PHP, картинки) на сервер. На Shared-хостинге — через панель (cPanel) или FTP. На VPS — через SSH (`scp` или `git clone`).
2.  **Установка Веб-сервера (Nginx или Apache):** Слушает 80-й (HTTP) и 443-й (HTTPS) порты, принимает запросы от браузеров и отдаёт им файлы. Без веб-сервера сайт не откроется.
3.  **Установка Базы данных (MySQL / MariaDB / PostgreSQL):** Хранит данные (новости, товары, пользователи). Без неё динамический сайт будет пустым или выдаст ошибку.
4.  **Установка Интерпретатора (PHP, Python, Node.js):** Выполняет скриптовый код и генерирует HTML, который затем отдаёт веб-сервер.
5.  **Настройка (Document Root):** Указание веб-серверу, в какой папке лежат файлы сайта (обычно `public_html` или `/var/www/html`).
6.  **Привязка домена и SSL:** Настройка A-записи на IP сервера. Установка SSL-сертификата (например, Let's Encrypt) для работы по HTTPS.

**Обязательный минимум:** Веб-сервер и База данных (для динамики). Остальное зависит от стека технологий.

## 3. Shared Hosting vs VPS

Разница заключается в уровне контроля и изоляции ресурсов.

### 3.1. Shared Hosting (виртуальный хостинг)
Один мощный физический сервер делится на множество аккаунтов (сайтов). Все используют общие ресурсы (CPU, RAM) и **одну операционную систему**.

| Плюсы | Минусы |
|---|---|
| Низкая стоимость | «Эффект шумного соседа»: нагрузка на соседний сайт влияет на твой |
| Настройка в 1 клик (cPanel/Plesk) | **Нет `root`-доступа** |
| Не требуется знание Linux | Ограниченный выбор ПО (обычно только PHP, MySQL, Nginx/Apache) |
| Безопасность сервера на провайдере | Нельзя ставить Docker, свои демоны, менять системные конфиги |

**Почему на Shared Hosting нет root-доступа:**
`root` — суперпользователь в Linux с неограниченными правами. На одном сервере живёт множество сайтов. Предоставление `root` хотя бы одному клиенту приведёт к:
1.  **Нарушению безопасности:** Владелец одного сайта получит доступ к данным всех остальных.
2.  **Нестабильности:** Случайное или намеренное изменение системного конфига обрушит работу всех сайтов.
Поэтому `root` остаётся у провайдера, а клиенты получают доступ через панель управления или ограниченный SSH (в пределах домашней папки). Для задач, требующих `root`, используется VPS.

### 3.2. VPS (Virtual Private Server)
Виртуальная машина, созданная с помощью виртуализации (KVM, VMware). Имеет выделенные ресурсы (свои ядра CPU, своя RAM) и полный `root`-доступ.

| Плюсы | Минусы |
|---|---|
| **Полный `root`-доступ:** установка любого ПО (Python, Docker, PostgreSQL) | Более высокая стоимость |
| Выделенные ресурсы (изоляция от соседей) | Самостоятельная настройка (SSH, firewall, обновления) |
| Возможность масштабирования (добавление RAM/CPU) | Ответственность за работоспособность ОС лежит на пользователе |
| Смена версий PHP, ядра, установка любых расширений | |

## 4. Другие виды хостинга

Помимо Shared и VPS, существуют и другие форматы:

| Вид | Суть | Применение |
|---|---|---|
| **Shared (виртуальный)** | Много сайтов на одном сервере, общие ресурсы, нет root | Блоги, визитки, небольшие сайты |
| **VPS (Virtual Private Server)** | Изолированная виртуальная машина с root | Растущие проекты, DevOps-задачи, кастомный стек |
| **Dedicated (выделенный)** | Целиком физический сервер, без соседей | Крупные интернет-магазины, высоконагруженные сервисы |
| **Cloud (облачный)** | Сайт работает на нескольких серверах, гибкое масштабирование, отказоустойчивость | Проекты с переменным трафиком |
| **Colocation (колокация)** | Клиент приносит свой сервер в дата-центр провайдера. Провайдер даёт место, питание и интернет | Компании, которым важен полный контроль над оборудованием |

**Логика масштабирования:** Shared → VPS → Dedicated/Cloud — переход по мере роста нагрузки и требований к контролю. Colocation используется при наличии собственного оборудования.

## 5. Панели управления хостингом

**Определение:** Графический веб-интерфейс для управления сайтами, доменами, почтой, базами данных и SSL без работы в консоли Linux. На Shared-хостинге это основной способ управления. На VPS панель устанавливается опционально для упрощения рутины.

**Основные функции:**
- Управление сайтами (домены, поддомены, алиасы).
- Управление файлами (файловый менеджер, FTP-аккаунты).
- Создание и управление базами данных (MySQL/PostgreSQL).
- Управление почтой (ящики, алиасы, автоответчики, антиспам).
- Установка SSL-сертификатов (например, Let's Encrypt).
- Резервное копирование (бэкапы).
- Установка CMS (WordPress, Joomla) в один клик.

**Популярные панели:**

| Панель | Особенности |
|---|---|
| **cPanel** | Самая распространённая в мире. Мощная, платная |
| **Plesk** | Популярна в Европе и России. Удобный интерфейс, поддержка Windows и Linux. Платная |
| **ISPmanager** | Российская разработка (ISPsystem). Дружелюбный интерфейс. Есть бесплатная Lite-версия |
| **VestaCP** | Бесплатная, открытая, простая |

## 6. Обязательное ПО виртуального хостинга (LAMP / LEMP)

На Shared-хостинге провайдер предустанавливает стандартный стек программ для работы сайта «из коробки».

**LAMP:**
- **L**inux — ОС.
- **A**pache — веб-сервер.
- **M**ySQL (или MariaDB) — СУБД.
- **P**HP — интерпретатор.

**LEMP** — то же самое, но вместо Apache используется **Nginx**. Nginx быстрее отдаёт статику и лучше держит нагрузку, поэтому используется чаще.

**Дополнительно в стандартный набор входит:**
- **FTP-сервер** (или SFTP) — для загрузки файлов.
- **Почтовый сервер** (SMTP/IMAP/POP3) — для создания ящиков вида `info@domain.ru`.
- **phpMyAdmin** — веб-интерфейс для управления БД.
- **SSL-сертификат** (Let's Encrypt).

Понимание стека необходимо для диагностики: если сайт на PHP не работает, в первую очередь проверяется версия PHP и наличие нужных расширений в панели управления.
