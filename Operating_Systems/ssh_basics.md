# SSH (Secure Shell)

## 1. Что такое SSH и зачем он нужен?

**SSH** — это сетевой протокол прикладного уровня для безопасного (зашифрованного) удаленного управления операционной системой.
- Работает по модели **клиент-сервер**.
- По умолчанию использует **TCP-порт 22**.
- Весь трафик (включая пароли и команды) шифруется, поэтому его нельзя перехватить (в отличие от старого Telnet).

## 2. Как работает SSH-соединение (упрощенно)

1. **TCP Handshake:** Клиент подключается к порту 22.
2. **Согласование версий:** Клиент и сервер обмениваются информацией о поддерживаемых версиях SSH.
3. **Обмен ключами (Diffie-Hellman):** Стороны генерируют общий секретный ключ сессии, который будет использоваться для симметричного шифрования трафика. (Этот ключ существует только на время сессии).
4. **Аутентификация:** Сервер проверяет, имеет ли клиент право доступа (по паролю или по ключу).
5. **Сессия:** После успешной аутентификации открывается зашифрованный канал, по которому передаются команды.

## 3. Методы аутентификации

### 3.1. По паролю (Password Authentication)
Клиент передает логин и пароль. Пароль шифруется, но этот метод считается устаревшим и небезопасным, так как пароли можно подобрать (brute-force). На современных серверах его обычно отключают.

### 3.2. По ключам (Public Key Authentication) — **Стандарт в IT**
Используется асимметричное шифрование.
У тебя есть **две** половинки одного ключа:
1. **Приватный ключ (Private key):** Хранится ТОЛЬКО у тебя на компьютере (файл `id_rsa` или `id_ed25519`). Его нельзя никому отдавать!
2. **Публичный ключ (Public key):** Его можно давать всем (файл `id_rsa.pub`). Он кладется на сервер в файл `~/.ssh/authorized_keys`.

**Как это работает:**
Сервер берет случайное сообщение, шифрует его публичным ключом и отправляет клиенту. Клиент расшифровывает его приватным ключом и отправляет ответ серверу. Если ответ сошелся — сервер понимает, что у клиента есть правильный приватный ключ, и пускает его.

## 4. Генерация и копирование ключей (Практика)

**Шаг 1. Сгенерировать пару ключей на клиенте (твоем ПК):**
```bash
ssh-keygen -t ed25519 -C "comment"
```
*Флаг `-t ed25519` указывает тип ключа (современный и безопасный, лучше устаревшего RSA).*

**Шаг 2. Скопировать публичный ключ на сервер:**
```bash
ssh-copy-id user@server_ip
```
*Утилита сама подключится по паролю и добавит содержимое твоего `id_ed25519.pub` в файл `~/.ssh/authorized_keys` на сервере.*

**Права доступа (Критически важно!):**
SSH не будет работать, если у файлов неправильные права.
- Папка `~/.ssh` — `chmod 700` (доступ только владельцу).
- Файл `~/.ssh/authorized_keys` — `chmod 600`.

## 5. Клиентская конфигурация (`~/.ssh/config`)
Чтобы не писать каждый раз `ssh -p 2222 root@192.168.1.100`, можно создать файл `~/.ssh/config`:

```text
Host myserver
    HostName 192.168.1.100
    User root
    Port 2222
    IdentityFile ~/.ssh/id_ed25519
```
Теперь для подключения достаточно ввести в терминале: `ssh myserver`.

## 6. Конфигурация сервера (`/etc/ssh/sshd_config`)
Сисадмин настраивает демон SSH. Вот ключевые директивы для безопасности:
- `Port 22` — можно сменить на нестандартный (например, 2222), чтобы уменьшить количество автоматических ботов, сканирующих порт 22.
- `PermitRootLogin no` — запретить входить напрямую под пользователем root (заходить нужно под обычным юзером, а потом повышать права через `sudo`).
- `PasswordAuthentication no` — запретить вход по паролям (разрешить только по ключам).
- `AllowUsers user1 user2` — явно указать, кому разрешено подключаться.

*После изменения конфига нужно перезапустить службу: `sudo systemctl restart sshd`.*

## 7. Полезные команды SSH

| Команда | Что делает |
|---|---|
| `ssh user@host` | Подключиться к серверу |
| `ssh -p 2222 user@host` | Подключиться на нестандартный порт |
| `ssh -v user@host` | Подключиться в режиме отладки (покажет, на каком этапе рукопожатия или аутентификации произошла ошибка) |
| `scp file.txt user@host:/path/` | Скопировать файл с локальной машины на сервер по SSH |
| `scp user@host:/path/file.txt .` | Скопировать файл с сервера на локальную машину |
| `exit` | Выйти из SSH-сессии |

## 8. SSH-туннели (Port Forwarding)

**Локальный туннель (`-L`)** — проброс порта с удаленного сервера на твою локальную машину.
*Пример:* На сервере (в закрытой сети) работает база данных PostgreSQL на порту 5432. Прямого доступа к ней нет. Мы делаем туннель:
```bash
ssh -L 5433:localhost:5432 user@server_ip
```
Теперь, подключившись к `localhost:5433` на своей машине, ты на самом деле будешь общаться с базой данных на сервере.
