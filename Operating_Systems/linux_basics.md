# Linux: работа с текстом, редакторы и анализ логов

## 1. Файловая система и навигация

Прежде чем редактировать файлы, нужно уметь по ним перемещаться. Вот базовый набор команд для ориентирования в Linux:

| Команда | Назначение |
|---|---|
| `ls` | Показать содержимое текущей директории |
| `ls -l` | Подробный список (права, владелец, размер, дата) |
| `ls -la` | Подробный список + скрытые файлы (начинаются с точки) |
| `ls -lh` | Подробный список с «человекочитаемыми» размерами (K, M, G) |
| `cd /path` | Перейти в директорию |
| `cd ..` | Перейти на уровень выше |
| `cd ~` | Перейти в домашнюю директорию |
| `pwd` | Показать текущий путь |
| `find /path -name "*.conf"` | Найти файлы по имени |
| `du -sh /path` | Показать размер директории (в «человекочитаемом» виде) |
| `df -h` | Показать свободное место на дисках |

> **Совет:** `ls -lt` сортирует файлы по времени изменения (сначала новые), `ls -lS` — по размеру (сначала большие). Это удобно, когда ищешь недавно изменённый конфиг или раздувшийся лог.

## 2. Консольные текстовые редакторы

В Linux серверы часто не имеют графического интерфейса, поэтому конфигурационные файлы редактируются прямо в терминале.

### nano (простой редактор)
| Действие | Команда |
|---|---|
| Запуск | `nano filename.txt` |
| Сохранение | `Ctrl + O`, затем `Enter` |
| Выход | `Ctrl + X` |

### vim (профессиональный редактор)
| Действие | Команда |
|---|---|
| Запуск | `vim filename.txt` |
| Вход в режим вставки | `i` |
| Выход из режима вставки | `Esc` |
| Сохранить и выйти | `:wq` + `Enter` |
| Выйти без сохранения | `:q!` + `Enter` |

> При запуске `vim` открывается в командном режиме (**Normal mode**). Текст набирается только после входа в режим вставки.

## 3. Базовые операции с файлами

```bash
touch filename.txt   # создать пустой файл
cat filename.txt     # вывести содержимое на экран
less filename.txt    # постраничный просмотр (удобнее для больших файлов)
head -n 10 file.txt  # первые 10 строк
tail -n 10 file.txt  # последние 10 строк
tail -f file.txt     # «следить» за файлом в реальном времени (для логов)
```

## 4. Права доступа к файлам и каталогам

В Linux у каждого файла есть **владелец** (пользователь) и **группа-владелец**. Права доступа определяют, что могут делать с файлом разные категории пользователей.

**Три категории пользователей:**
- **Владелец (User, `u`)** — пользователь, которому принадлежит файл.
- **Группа (Group, `g`)** — пользователи, входящие в группу-владельца файла.
- **Остальные (Others, `o`)** — все остальные пользователи системы.

**Три типа прав:**
| Право | Обозначение | Для файла | Для каталога |
|---|---|---|---|
| **Чтение** | `r` (4) | Просмотр содержимого | Просмотр списка файлов (`ls`) |
| **Запись** | `w` (2) | Изменение содержимого | Создание/удаление файлов |
| **Выполнение** | `x` (1) | Запуск как программы | Вход в каталог (`cd`) |

> **Важно:** чтобы зайти в каталог (`cd`) или получить доступ к файлам внутри него, нужно иметь право **выполнения** (`x`) на этот каталог, даже если есть право чтения.

**Просмотр прав:** `ls -l` показывает права в виде строки из 10 символов, например: `-rwxr-xr--`.
- Первый символ: тип (`-` файл, `d` каталог, `l` симлинк).
- Следующие три: права владельца (`rwx`).
- Следующие три: права группы (`r-x`).
- Последние три: права остальных (`r--`).

**Числовая (восьмеричная) запись прав:** каждое право кодируется числом (r=4, w=2, x=1), сумма трёх прав даёт цифру от 0 до 7 для каждой категории.

| Число | Символы | Значение |
|---|---|---|
| 0 | `---` | Нет прав |
| 1 | `--x` | Только выполнение |
| 2 | `-w-` | Только запись |
| 3 | `-wx` | Запись и выполнение |
| 4 | `r--` | Только чтение |
| 5 | `r-x` | Чтение и выполнение |
| 6 | `rw-` | Чтение и запись |
| 7 | `rwx` | Полные права |

**Популярные комбинации:**
| Комбинация | Символы | Применение |
|---|---|---|
| `644` | `rw-r--r--` | Конфигурационные файлы |
| `600` | `rw-------` | Приватные ключи (`~/.ssh/id_ed25519`) |
| `700` | `rwx------` | Приватные директории (`~/.ssh`) |
| `755` | `rwxr-xr-x` | Исполняемые скрипты, публичные директории |
| `777` | `rwxrwxrwx` | Полный доступ для всех (небезопасно) |

**Изменение прав — `chmod`:**
```bash
chmod 755 script.sh        # числовой способ (rwxr-xr-x)
chmod u+x script.sh        # символьный способ (добавить выполнение владельцу)
chmod go-w file.txt        # убрать запись у группы и остальных
chmod -R 644 /var/www/     # рекурсивно для всех файлов в директории
```

**Смена владельца — `chown` и `chgrp`:**
```bash
chown user1 file.txt            # сменить владельца на user1
chown user1:group1 file.txt     # сменить владельца и группу
chown -R user1:group1 /var/www/ # рекурсивно
chgrp group1 file.txt           # сменить только группу
```

## 5. Передача файлов между серверами

Для копирования файлов между машинами в Linux используются утилиты, работающие поверх SSH. Они безопасны (трафик шифруется) и не требуют установки дополнительного ПО.

### 5.1. `scp` (Secure Copy) — простой и быстрый
Используется для разовой передачи файлов или небольших директорий. Синтаксис похож на `cp`.

**Локально → удалённо:**
```bash
scp file.txt user@remote_ip:/remote/path/
scp -r local_dir user@remote_ip:/remote/path/   # рекурсивно (для директорий)
```

**Удалённо → локально:**
```bash
scp user@remote_ip:/remote/path/file.txt /local/path/
```

**Особенности:** простой синтаксис, но не поддерживает докачку (при обрыве передача начинается заново) и неэффективен для множества мелких файлов.

### 5.2. `rsync` — стандарт для бэкапов и синхронизации
Синхронизирует файлы между хостами, передавая только различия (инкрементально). Идеален для регулярных задач.

**Локально → удалённо:**
```bash
rsync -avz local_dir/ user@remote_ip:/remote/path/
```
**Ключевые флаги:**
- `-a` — архивный режим (сохраняет права, время, симлинки).
- `-v` — подробный вывод.
- `-z` — сжатие при передаче.

**Удалённо → локально:**
```bash
rsync -avz user@remote_ip:/remote/path/ /local/path/
```

**Докачка при обрыве (большие файлы):**
```bash
rsync -avz --partial --progress user@remote_ip:/bigfile /local/
```
> **Важно:** завершающий слэш в путях-источниках имеет значение. `dir/` копирует **содержимое** директории, `dir` — саму директорию.

### 5.3. `sftp` (Secure FTP) — интерактивный режим
Запускает сессию, похожую на FTP, но поверх SSH. Удобен для ручного управления файлами на сервере.

```bash
sftp user@remote_ip
```
**Команды внутри сессии:**
```bash
ls          # список файлов на удалённом хосте
put file.txt    # загрузить файл на сервер
get file.txt    # скачать файл с сервера
mkdir dir       # создать директорию
cd /path        # перейти в директорию
exit            # выйти
```

## 6. Перенаправление потоков ввода/вывода

В Linux у каждой программы есть три стандартных потока:
| Поток | Дескриптор | Назначение |
|---|---|---|
| **stdin** | `0` | Стандартный ввод (клавиатура) |
| **stdout** | `1` | Стандартный вывод (успешный результат) |
| **stderr** | `2` | Стандартный поток ошибок |

**Операторы:**
| Оператор | Что делает |
|---|---|
| `>` | Перенаправить stdout в файл (перезапишет файл) |
| `>>` | Перенаправить stdout в файл (добавит в конец) |
| `2>` | Перенаправить stderr в файл (ошибки пишутся в файл, а не на экран) |
| `\|` (pipe/труба) | Передать вывод одной команды на вход другой |

### 6.1. Продвинутые приёмы

- **`2>&1`** — «склеить» stdout и stderr, чтобы **оба** потока ушли в одно место.
  ```bash
  ls /nonexistent /bin > all_output.txt 2>&1
  # Ошибка и успешный вывод будут в одном файле
  ```

- **`tee`** — «разветвитель»: показывает вывод на экране **и** одновременно пишет его в файл.
  ```bash
  echo "Hello" | tee output.txt
  # "Hello" появится на экране и будет записано в output.txt
  ```

- **`xargs`** — превращает stdout одной команды в аргументы для другой.
  ```bash
  find /var/log -name "*.log" | xargs grep "ERROR"
  # Ищет "ERROR" во всех найденных .log-файлах
  ```

## 7. Утилиты обработки текста

Используются для анализа логов и фильтрации данных.

### grep — поиск строк по шаблону
```bash
grep "404" access.log
```
| Флаг | Значение |
|---|---|
| `-i` | Игнорировать регистр |
| `-v` | Инверсия: показать строки **без** совпадений |
| `-r` | Рекурсивный поиск по директориям |
| `-E` | Использовать расширенные регулярные выражения (`grep -E "error\|fail"`) |

### awk — обработка по колонкам
По умолчанию разделитель колонок — пробел или табуляция.
```bash
awk '{print $1}' file.txt   # вывести только 1-ю колонку (например, IP-адреса)
awk '{print $1, $7}' file.txt  # 1-я и 7-я колонки
awk -F ':' '{print $1}' /etc/passwd  # указать разделитель вручную (двоеточие)
```

### sort — сортировка
| Команда | Значение |
|---|---|
| `sort` | По алфавиту |
| `sort -n` | Числовая сортировка (чтобы `10` было больше `2`) |
| `sort -r` | Обратный порядок |
| `sort -k 2 -n` | Сортировать по 2-й колонке как числа |
| `sort -t ':' -k 3 -n` | Сортировать по 3-й колонке с разделителем «:» |

### uniq — удаление дубликатов
> **Важно:** работает только с отсортированным списком.
```bash
uniq -c   # подсчитать количество повторений
```

### sed — потоковый редактор
```bash
sed 's/old/new/g' file.txt   # заменить все вхождения "old" на "new"
sed -n '/ERROR/p' file.txt   # показать только строки с "ERROR" (как grep)
sed '1d' file.txt            # удалить первую строку
```
> `s` — substitute, `g` — global (все вхождения, а не только первое).

## 8. Управление процессами и сервисами (systemd)

Современные Linux-системы используют **systemd** как систему инициализации и менеджер служб. Понимание `systemctl` и `journalctl` — это **обязательный навык** для 2-й линии поддержки.

### systemctl — управление сервисами
| Команда | Назначение |
|---|---|
| `systemctl status nginx` | Проверить статус сервиса (работает/упал/остановлен) |
| `systemctl start nginx` | Запустить сервис |
| `systemctl stop nginx` | Остановить сервис |
| `systemctl restart nginx` | Перезапустить сервис |
| `systemctl reload nginx` | Перечитать конфиг без перезапуска (если поддерживается) |
| `systemctl enable nginx` | Включить автозапуск при загрузке системы |
| `systemctl disable nginx` | Отключить автозапуск |
| `systemctl is-active nginx` | Проверить, активен ли сервис (вернёт `active` или `inactive`) |
| `systemctl list-units --type=service` | Список всех сервисов |

**Типичный сценарий диагностики:** если сайт отдаёт **502 Bad Gateway**, первое, что нужно сделать — проверить статус бэкенд-сервиса:
```bash
systemctl status myapp
```
Если сервис в состоянии `failed` — смотрим его логи (см. ниже).

### journalctl — просмотр логов systemd
`journalctl` — это централизованный инструмент для чтения логов, которые собирает systemd.

| Команда | Назначение |
|---|---|
| `journalctl -u nginx` | Логи конкретного сервиса (`-u` = unit) |
| `journalctl -u nginx -n 100` | Последние 100 строк логов сервиса |
| `journalctl -u nginx -f` | «Следить» за логами в реальном времени |
| `journalctl -b` | Логи текущей загрузки системы |
| `journalctl --since "1 hour ago"` | Логи за последний час |
| `journalctl --since today` | Логи за сегодня |
| `journalctl -p err` | Только ошибки (уровень `err` и выше) |

> **Почему это важно:** `journalctl` заменяет «ручное» чтение файлов в `/var/log/`. Он умеет фильтровать по сервису, времени и уровню важности. Это стандарт диагностики в современных дистрибутивах (Ubuntu, CentOS, Debian).

## 9. Управление пакетами (APT / YUM / DNF)

В зависимости от дистрибутива используются разные пакетные менеджеры. Для сисадмина важно уметь ставить, обновлять и удалять пакеты.

| Дистрибутив | Менеджер | Основные команды |
|---|---|---|
| **Ubuntu / Debian** | `APT` | `apt update`, `apt install <pkg>`, `apt remove <pkg>`, `apt upgrade` |
| **CentOS 7 / RHEL 7** | `YUM` | `yum install <pkg>`, `yum remove <pkg>`, `yum update` |
| **CentOS 8+ / Fedora / RHEL 8+** | `DNF` | `dnf install <pkg>`, `dnf remove <pkg>`, `dnf update` (почти полный аналог YUM) |

> **Ключевое отличие:** APT работает с пакетами `.deb`, а YUM/DNF — с `.rpm`. DNF — это современная замена YUM с более быстрым разрешением зависимостей.

**Базовый цикл обновления системы (Ubuntu):**
```bash
apt update          # обновить список доступных пакетов
apt upgrade         # обновить установленные пакеты
apt autoremove      # удалить «осиротевшие» зависимости
```

## 10. Практика: анализ логов и типовые кейсы

### Кейс 1. Вывод MX-записей и сортировка по приоритету
**Задача:** вывести MX-записи для `gmail.com` и отсортировать по приоритету.
```bash
host -t MX gmail.com | awk '{print $6, $7}' | sort -n
```
**Объяснение:** `host` выдаёт строки, `awk` оставляет только приоритет (6-я колонка) и адрес (7-я колонка), `sort -n` сортирует по числам.

### Кейс 2. Подсчёт IP-адресов из лога
**Задача:** найти IP, которые обращались к поддомену, посчитать их и отсортировать по убыванию.
```bash
grep "zxc.okerpet.beget.tech" logs.txt | awk '{print $1}' | sort | uniq -c | sort -nr
```
**Объяснение:**
1. `grep` — фильтрует строки с нужным поддоменом.
2. `awk '{print $1}'` — вытаскивает только IP-адреса.
3. `sort` — сортирует IP (обязательно для работы `uniq`).
4. `uniq -c` — считает количество повторений.
5. `sort -nr` — сортирует по числам в обратном порядке (самые частые наверху).

### Кейс 3. Перенаправление ошибок
**Задача:** записать ошибку выполнения команды в файл `errors.txt`.
```bash
ls /some/directory 2> errors.txt
```
**Объяснение:** `2>` перенаправляет поток ошибок (stderr) в файл.

### Кейс 4. Сквозная диагностика упавшего сервиса
**Задача:** сайт отдаёт 502. Найти причину.
```bash
# 1. Смотрим статус бэкенд-сервиса
systemctl status myapp

# 2. Если сервис упал — смотрим его логи
journalctl -u myapp -n 50 --no-pager

# 3. Если в логах видим, что сервис жив, но не отвечает — проверяем, слушает ли он порт
ss -tulpn | grep 8080
```
**Объяснение:** это стандартная цепочка диагностики для 2-й линии. `systemctl status` показывает, жив ли процесс, `journalctl` — почему он упал, `ss` — слушает ли он нужный порт.
