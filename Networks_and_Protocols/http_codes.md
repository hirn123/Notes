# Коды ответов HTTP

HTTP-коды — это трехзначные числа, которые сервер возвращает клиенту (браузеру или API-клиенту). Первая цифра указывает на класс ответа.

| Группа | Значение | Кто виноват / Где искать |
|---|---|---|
| **2xx** | Успех | Всё работает штатно. |
| **3xx** | Редирект | Нужно перейти по другому адресу. |
| **4xx** | Ошибка клиента | Ошибка в запросе (опечатка, нет прав). Искать в браузере/клиенте. |
| **5xx** | Ошибка сервера | Сервер не смог обработать корректный запрос. Искать в логах Nginx и бэкенда. |

---

## 2xx — Успех

### 200 OK
- **Что значит:** Запрос выполнен успешно. Сервер отдал HTML-страницу, JSON-ответ или файл.
- **Технически:** Nginx нашел статичный файл, ИЛИ бэкенд успешно выполнил код и вернул результат.
- **Действия:** Ничего.
- **Пример:** Открытие главной страницы `google.com`, успешный `GET /users/1` в API.

### 201 Created (Бонус к API)
- **Что значит:** Объект успешно создан.
- **Пример:** Бот отправляет `POST /send_message`, сообщение создается на сервере, ответ — `201`.

---

## 3xx — Редиректы (Перенаправления)

### 301 Moved Permanently (Навсегда)
- **Что значит:** Ресурс переехал на новый URL **навсегда**. Браузер обязан закэшировать этот редирект.
- **Технически:** Админ настроил `return 301` в Nginx. Поисковики передают весь рейтинг (вес) старой страницы новой.
- **⚠️ Подводный камень:** Если ты ошибочно поставишь 301, браузер пользователя запомнит его. Даже если ты уберешь редирект, пользователь будет ходить по старому адресу, пока вручную не почистит кэш.
- **Пример:** Переезд с `http://site.ru` на `https://site.ru` или смена домена `oldbrand.com` -> `newbrand.com`.

### 302 Found (Временно)
- **Что значит:** Ресурс временно доступен по другому адресу. Браузер не кэширует переход надолго.
- **Технически:** Используется для временных заглушек, при авторизации (перекидывание на `/login`), при A/B тестах.
- **Пример:** Пользователь не авторизован, его временно перекидывает на страницу логина. Как только он войдет — редирект перестанет срабатывать.

---

## 4xx — Ошибки клиента (Пользователь сделал что-то не так)

### 401 Unauthorized (Не авторизован) — *Частая путаница с 403*
- **Что значит:** Сервер не знает, кто ты.
- **Технически:** Не передан токен авторизации, истек срок действия куки, неверный логин/пароль.
- **Действия:** Проверить, передается ли заголовок `Authorization`.

### 403 Forbidden (Доступ запрещен)
- **Что значит:** Сервер знает, кто ты (ты авторизован), но у тебя **нет прав** на это действие.
- **Технически:**
  1. Неправильные права на файл в Linux (`chmod 000`).
  2. Закрыт доступ к скрытым файлам (`.git`, `.env`) в конфиге Nginx.
  3. IP заблокирован файрволом (WAF).
- **Действия:** Проверить `ls -la` (права на файлы), логи Nginx, правила фаервола.
- **Пример:** Пользователь пытается зайти в `/admin`, но он не админ. Или ты пытаешься скачать файл с паролями `site.ru/.env`, а Nginx настроен его блокировать.

### 404 Not Found (Не найдено)
- **Что значит:** Такого ресурса не существует.
- **Технически:** Опечатка в URL. Файл удален. Или бэкенд-приложение не знает такого маршрута (route).
- **Действия:** Убедиться, что файл на месте, проверить маршруты бэкенда.
- **Пример:** Опечатка `site.ru/abaut` вместо `site.ru/about`.

---

## 5xx — Ошибки сервера (Сломался бэкенд или инфраструктура)
Это самый важный блок для 2-й линии поддержки. Все эти ошибки означают: «Клиент отправил нормальный запрос, но у нас на сервере что-то сломалось».

### 500 Internal Server Error (Внутренняя ошибка)
- **Что значит:** Бэкенд начал обрабатывать запрос и **упал** из-за ошибки в коде.
- **Технически:** Деление на ноль, синтаксическая ошибка, необработанное исключение, потеряна связь с БД.
- **Действия:** Идти в логи бэкенда (например, `journalctl -u gunicorn` или `/var/log/php/error.log`), искать `Exception`.
- **Пример:** В Python-скрипте забыли обработать ситуацию, когда пользователь ничего не ввел.

### 502 Bad Gateway (Плохой шлюз)
- **Что значит:** Nginx (швейцар) передал запрос бэкенду, но **бэкенд умер** и не ответил.
- **Технически:** Процесс бэкенда убит OOM Killer'ом (не хватило RAM), или перезагружается. Nginx не может достучаться до сокета.
- **Действия:** Проверить `systemctl status app`, слушает ли бэкенд порт `ss -tulpn`. Посмотреть логи Nginx (`/var/log/nginx/error.log`).
- **Пример:** Бэкенд упал из-за нехватки памяти. Nginx говорит: «Я постучался, а там никого нет».

### 503 Service Unavailable (Сервис недоступен)
- **Что значит:** Сервер работает, но **отказывается** обслуживать запрос прямо сейчас.
- **Технически:**
  1. Технические работы (админ включил заглушку).
  2. Перегрузка (закончились воркеры).
  3. Лимиты подключений к БД.
- **Действия:** Проверить нагрузку (`top`, `htop`), проверить настройки балансировщика, лимиты БД.
- **Пример:** «Черная пятница», сайт упал от наплыва пользователей.

### 504 Gateway Timeout (Таймаут шлюза)
- **Что значит:** Nginx передал запрос бэкенду, а тот **не ответил за отведенное время** (например, 60 секунд). Соединение закрылось по таймауту.
- **Технически:** Бэкенд жив, но завис. Выполняет тяжелый SQL-запрос или ждет ответа от внешнего API.
- **Действия:** Искать «медленные» запросы в БД (`slow query log`), смотреть таймауты в конфиге Nginx.
- **Пример:** Бэкенд стучится в банковский шлюз для проведения оплаты, а банк тупит 60 секунд. Nginx не выдерживает и обрывает соединение.

## 💡 Шпаргалка для собеса: В чем разница между 500, 502, 503 и 504?

Если спросят «Сайт отдает ошибку, как понять какая?»:
1.  **500:** Бэкенд живой, но код сломался (ошибка в логике).
2.  **502:** Бэкенд **умер** (Nginx не может к нему подключиться).
3.  **503:** Бэкенд живой, но **не может** брать запросы (перегрузка или техработы).
4.  **504:** Бэкенд живой, но **очень долго думает** (таймаут).

**Как проверить руками:**
```bash
# Посмотреть заголовки ответа (какой код вернул сервер)
curl -I https://example.com

# Проверить ошибки 502/503/504 на тестовых сервисах
curl -I https://httpstat.us/502
curl -I https://httpstat.us/503
curl -I https://httpstat.us/504
```
