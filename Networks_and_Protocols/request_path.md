## Что происходит, когда я ввожу `https://example.com` и нажимаю Enter

### 1. Проверка кэша (Browser & OS)

Браузер сначала не лезет в интернет, а проверяет, не знает ли он уже этот сайт:

- кэш браузера (история, куки, DNS-кэш);
- если нет — спрашивает ОС (Windows/Linux), которая смотрит файл `hosts` и системный DNS-кэш.

Если нигде нет — идём дальше.

### 2. DNS-резолвинг (поиск IP-адреса)

Браузеру нужен IP сервера: по проводам бегают IP, а не буквы.

1. Браузер отправляет запрос локальному DNS-серверу (обычно роутер или провайдер).
2. Если провайдер не знает, запрос идёт вверх по иерархии: корневые серверы → серверы зоны `.com` → авторитативные серверы домена `example.com`.
3. Результат: браузер получает IP-адрес (например, `93.184.216.34`).

### 3. TCP Handshake (установка соединения)

Браузер знает IP, теперь нужно установить надёжное TCP-соединение на порт `443` (для HTTPS).

```
Браузер: SYN      (я хочу соединиться)
Сервер:  SYN-ACK  (я согласен)
Браузер: ACK      (принято)
```

Соединение установлено.

### 4. TLS Handshake (шифрование HTTPS)

Раз используется HTTPS, нужно договориться о шифровании, чтобы никто не подслушал трафик.

1. Браузер отправляет **Client Hello** (поддерживаемые версии TLS, шифры).
2. Сервер отвечает **Server Hello** и присылает свой SSL-сертификат.
3. Браузер проверяет сертификат: не истёк ли срок, выдан ли удостоверяющим центром, совпадает ли имя домена.
4. Стороны обмениваются ключами. С этого момента трафик зашифрован.

### 5. HTTP-запрос

Теперь браузер может безопасно попросить страницу.

```
GET / HTTP/1.1   (или HTTP/2)
```

Заголовки:

| Заголовок | Назначение |
|---|---|
| `Host: example.com` | Какой сайт просим |
| `User-Agent: Chrome...` | Какой у меня браузер |
| `Cookie: ...` | Мои данные авторизации/настроек |
| `Accept: text/html` | Я хочу HTML |

### 6. Обработка на сервере (Nginx / Apache)

Запрос долетает до сервера, там его встречает веб-сервер (обычно Nginx или Apache).

- **Статичный файл** (картинка, CSS, просто HTML) — отдаётся сразу.
- **Нужна логика** (авторизация, поиск по базе) — Nginx работает как reverse proxy и передаёт запрос бэкенду (Python, PHP, Node.js) через внутренний порт (например, `8080`) или unix-socket.

### 7. Работа бэкенда (Backend & Database)

Бэкенд (например, на Python/Django) принимает запрос:

1. Выполняет код: проверяет куки, достаёт данные из БД (PostgreSQL/MySQL).
2. Собирает HTML-страницу (например, через шаблонизатор) и отдаёт её обратно Nginx'у.

### 8. HTTP-ответ (Response)

Nginx формирует ответ и отправляет его браузеру:

- **Статус-код:** `200 OK` (если всё хорошо) или `404 Not Found` (если бэкенд не нашёл страницу).
- **Заголовки:** `Content-Type: text/html`, `Set-Cookie` (если сервер хочет поставить новую куку).
- **Тело ответа:** сам HTML-код страницы.

### 9. Парсинг и рендеринг (Browser Rendering)

Браузер получает HTML и начинает его «читать»:

1. Строит DOM-дерево.
2. Находит внутри HTML ссылки на картинки, CSS-стили и JS-скрипты.
3. **Важно:** для каждой картинки и скрипта браузер снова выполняет шаги 2, 3, 4 и 5 (заново ищет IP, ставит TCP/TLS-соединение и делает запрос), если они не закэшированы.
4. Применяет CSS, выполняет JS и отрисовывает сайт на экране.

---

> Посмотреть всё это можно в баше: `curl -v https://example.com`
