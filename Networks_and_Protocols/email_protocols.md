# Почтовые протоколы: SMTP, POP3, IMAP

## 1. Основные протоколы

| Протокол | Роль | Порты | Аналогия |
|---|---|---|---|
| **SMTP** | Отправка писем (Push) | 25 — сервер-сервер, 587 — STARTTLS, 465 — SSL/TLS | Почтовый курьер: забирает письмо из твоего ящика и несёт адресату |
| **POP3** | Скачивание писем на устройство; обычно удаляет их с сервера | 110 — без шифрования, 995 — SSL/TLS | Ты приходишь на почту, забираешь бумажное письмо домой, а ячейка становится пустой |
| **IMAP** | Хранение писем на сервере и синхронизация состояния между устройствами | 143 — без шифрования, 993 — SSL/TLS | Облачный диск (Google Docs): работаешь с документом, и изменения видят все |

### SMTP (Simple Mail Transfer Protocol) — отправка
- **Роль:** только отправляет письма. Работает по принципу **Push**.
- **Порты:**
  - `25` — для обмена почтой между серверами. Часто блокируется провайдерами для конечных пользователей для борьбы со спамом.
  - `587` — стандартный порт для **отправки почты клиентом** (MUA → MTA). Использует **STARTTLS** (сначала незашифрованное соединение, затем апгрейд до TLS).
  - `465` — устаревший порт, но всё ещё используется для **Implicit TLS** (шифрование с самого начала соединения).

### POP3 (Post Office Protocol v3) — скачивание
- **Роль:** забирает письма с сервера на устройство. Обычно удаляет их с сервера после скачивания.

### IMAP (Internet Message Access Protocol) — синхронизация
- **Роль:** держит письма на сервере и синхронизирует их состояние между всеми устройствами.

## 2. Архитектура электронной почты: MUA, MTA, MDA

Чтобы понимать, что происходит с письмом, важно знать четыре компонента.

| Компонент | Расшифровка | Роль | Примеры |
|---|---|---|---|
| **MUA** | Mail User Agent | Почтовый клиент. С ним взаимодействует человек. Позволяет читать и писать письма | Thunderbird, Outlook, веб-интерфейс Gmail |
| **MSA** | Message Submission Agent | Принимает письмо от MUA и передаёт его в MTA. Часто совмещён с MTA | Входит в состав Postfix/Exim |
| **MTA** | Mail Transfer Agent | Почтовый сервер. Отвечает за **маршрутизацию и передачу** писем между серверами по SMTP | Postfix, Exim, Sendmail, серверы Яндекса/Google |
| **MDA** | Mail Delivery Agent | **Доставляет** письмо от MTA в конкретный почтовый ящик пользователя | Dovecot, Procmail |

**Важно:** MTA и MDA могут находиться на одном сервере или на разных. MTA находит сервер получателя по **MX-записи** в DNS.

## 3. Полный путь письма (пример)

Отправитель: `info@yandex.ru` → Получатель: `info@phone-test.ru`

1.  **MUA** (веб-интерфейс Яндекс.Почты) отправляет письмо на **MTA Яндекса** по SMTP (порт 587 или 465).
2.  **MTA Яндекса** смотрит **MX-запись** для `phone-test.ru` в DNS и узнаёт адрес **MTA Beget**.
3.  **MTA Яндекса** передаёт письмо на **MTA Beget** по SMTP (порт 25).
4.  **MTA Beget** передаёт письмо своему **MDA** (например, Dovecot).
5.  **MDA Beget** раскладывает письмо в почтовый ящик `info@phone-test.ru`.
6.  Получатель открывает **MUA** и забирает письмо по **IMAP** (порт 993) или **POP3** (порт 995).

## 4. Аутентификация почты: SPF, DKIM, DMARC

Если письма с твоего домена попадают в спам, почти всегда проблема в **DNS-записях**, а не в самом почтовом сервере. Это три технологии, которые доказывают, что письмо легитимно.

| Технология | Что проверяет | Где настраивается | Пример записи TXT |
|---|---|---|---|
| **SPF** (Sender Policy Framework) | **Кто** имеет право отправлять почту от имени домена. Список IP/серверов | TXT-запись на основном домене | `v=spf1 include:_spf.google.com ~all` |
| **DKIM** (DomainKeys Identified Mail) | **Цифровая подпись** письма. Проверяет, что содержимое не было изменено | TXT-запись на поддомене `selector._domainkey.example.com` | `v=DKIM1; k=rsa; p=MIIBIjANBg...` |
| **DMARC** (Domain-based Message Authentication) | **Политика** для получателя: что делать, если SPF/DKIM не прошли | TXT-запись на `_dmarc.example.com` | `v=DMARC1; p=quarantine; rua=mailto:dmarc@example.com` |

**Политики DMARC (`p=`):**
- `p=none` — ничего не делать (только собирать отчёты).
- `p=quarantine` — помещать в спам.
- `p=reject` — отклонять письмо.

**Диагностика:** `dig example.com TXT` — покажет SPF и DMARC. `dig selector._domainkey.example.com TXT` — покажет DKIM.

## 5. Практическая диагностика

Чтобы проверить, работает ли почтовый сервер, используются три утилиты.

**1. `telnet` — базовая проверка соединения:**
```bash
telnet mail.example.com 25
```
Если соединение установлено, сервер ответит приветствием (например, `220 mail.example.com ESMTP`). Набери `QUIT` для выхода.

**2. `openssl s_client` — проверка шифрования (TLS/SSL):**
```bash
# Проверка STARTTLS (порт 587)
openssl s_client -connect mail.example.com:587 -starttls smtp

# Проверка Implicit TLS (порт 465)
openssl s_client -connect mail.example.com:465
```
Покажет цепочку сертификатов и параметры шифрования.

**3. `swaks` — «швейцарский нож» для SMTP:**
```bash
swaks --to test@example.com \
      --from your@example.com \
      --server mail.example.com:587 \
      --auth LOGIN \
      --auth-user your@example.com \
      --auth-password 'password' \
      --tls
```
Позволяет протестировать полный цикл отправки с аутентификацией и шифрованием.
