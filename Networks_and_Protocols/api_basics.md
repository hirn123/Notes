# API (Application Programming Interface)

## 1. Определение

**API** — это программный интерфейс приложения. Набор правил и инструментов, с помощью которых одна программа может взаимодействовать с другой, не имея доступа к её внутренней реализации.

> **Аналогия (ресторан):**
> - Клиент (одна программа) делает заказ.
> - Официант (API) принимает заказ по строгим правилам и передаёт его.
> - Кухня (бэкенд/база данных) готовит еду.
> - Клиент не имеет доступа к кухне и не знает, как именно готовится блюдо, но получает результат.

## 2. Зачем нужен API

- **Изоляция** — скрывает внутреннюю логику и базу данных от прямого доступа.
- **Безопасность** — разрешает выполнение только строго определённых операций.
- **Интеграция** — позволяет приложениям (например, мобильному приложению и серверу) обмениваться данными.

## 3. REST API (самый популярный стандарт)

**REST** (Representational State Transfer) — архитектурный стиль, где взаимодействие строится вокруг ресурсов (объектов) и HTTP-методов (CRUD).

| Метод | Назначение | Пример |
|---|---|---|
| `GET` | Получение данных | `GET /users/1` |
| `POST` | Создание нового объекта | `POST /users` |
| `PUT` / `PATCH` | Обновление объекта (PUT — полная замена, PATCH — частичное) | `PUT /users/1` |
| `DELETE` | Удаление объекта | `DELETE /users/1` |

## 4. Структура API-запроса

1. **URL (Endpoint)** — адрес ресурса, например `https://api.github.com/users/torvalds`.
2. **Метод HTTP** — `GET`, `POST`, `PUT`, `DELETE`.
3. **Заголовки (Headers)** — служебная информация. Ключевой заголовок для доступа: `Authorization: Bearer <токен>` (API-ключ).
4. **Тело (Body)** — передаваемые данные (используется в `POST` и `PUT`).

## 5. Формат данных: JSON

Стандартный формат обмена данными в современных API. Представляет собой текстовый формат, похожий на словари в Python.

```json
{
  "id": 1,
  "name": "Ivan",
  "role": "admin"
}
```
